Consultas SQL

Receitas prontas para criar e editar dados, catálogo de comandos e um formatador que explica a consulta passo a passo e converte entre SQLite, T-SQL e PostgreSQL. Tudo roda no seu navegador: nada do que você digita é enviado a lugar nenhum.

Conceitos essenciais (leia uma vez, ajuda em tudo)
Ordem de execução
Você escreve SELECT primeiro, mas o banco executa nesta ordem: FROM / JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT / TOP. Por isso um apelido criado no SELECT normalmente não pode ser usado no WHERE, mas pode ser usado no ORDER BY.
WHERE × HAVING
WHERE filtra linhas antes de agrupar. HAVING filtra grupos depois de agrupar (é o lugar de COUNT, SUM, AVG…).
NULL
NULL significa "valor desconhecido", não zero nem texto vazio. coluna = NULL nunca é verdadeiro: use IS NULL. COUNT(coluna) ignora NULL; COUNT(*) conta linhas. Qualquer conta com NULL dá NULL (use COALESCE).
Tipos de JOIN
INNER: só linhas com correspondência nos dois lados. LEFT: todas da esquerda, mesmo sem correspondência (a direita vem NULL). FULL: todas dos dois lados. CROSS: todas as combinações.
Dialetos
SELECT, JOIN, GROUP BY, CASE e funções de janela são praticamente iguais em todos os bancos. O que muda são nomes de funções, datas, limite de linhas e criação de tabelas. A chave abaixo troca as receitas e o catálogo entre SQLite, T-SQL (SQL Server) e PostgreSQL.
Editando dados com segurança
UPDATE e DELETE sem WHERE afetam todas as linhas. Antes, rode um SELECT com o mesmo WHERE para ver o que será afetado, faça backup e use uma transação (BEGIN … ROLLBACK ou COMMIT).
Maiúsculas e minúsculas
Palavras-chave (SELECT, from…) não diferenciam maiúsculas. Textos entre aspas simples podem diferenciar, conforme o banco e a configuração (collation).
